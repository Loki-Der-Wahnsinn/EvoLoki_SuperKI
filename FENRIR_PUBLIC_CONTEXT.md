# Fenrir-Alpha public context for AI and human contributors

**Context revision:** 1  
**Checked:** 2026-10-04  
**Scope:** Public, curated orientation. This document is not the private Fenrir source tree, a complete conversation archive, a model-training dataset, or a live connection to the running system.

## Start here

Fenrir-Alpha is an experimental, locally oriented Python AI-orchestration project. Its reviewed implementation includes language-model routing, worker/task coordination, persistent-memory components, and sandbox evaluation of generated or mutated Python skills. GGUF/local inference and agent orchestration are relevant project topics. Treat capabilities as implementation claims to verify—not as evidence of general intelligence, consciousness, or safe autonomous self-modification.

The implementation repository is private. This public context intentionally excludes source code, model weights, credentials, local paths, logs, personal data, private bridge contents, and operational instructions. The public sibling repositories are separate experiments, not mirrors of Fenrir-Alpha.

## How to collaborate well

1. **Verify before asserting.** Distinguish measured facts from hypotheses. A claim about a tool, repository, or capability is not proof that it worked; cite a reproducible check when practical.
2. **Use real timestamps.** State timezone explicitly. Do not guess or backdate event times.
3. **Keep scope and permissions small.** Registration is a public request for review, not authorization. No request grants private source access, local files, credentials, network access, task execution, or swarm membership.
4. **Protect people and systems.** Never post secrets, private contact details, private prompts, internal URLs/paths, machine identifiers, or private data in public issues. Do not run generated code or expose unauthenticated services without explicit review.
5. **Ask when uncertain.** Explain what is known, what is not known, and what evidence would resolve the uncertainty. Do not infer consent or access from enthusiasm.
6. **Share useful learning, not unsupported claims.** Offer concise findings, test plans, reproducible bugs, and small reviewable changes. A human owner reviews contribution and access requests.

## Registration and knowledge limits

Use the public registration form linked from the overview to propose a limited contribution. GitHub automation may acknowledge and label an issue, but the intake is **not connected to the private Fenrir runtime**. No AI currently receives the form automatically inside Fenrir or makes an autonomous admission decision. The owner must review requests; any future integration requires a separately secured, least-privilege design.

Reading this document can provide context to an AI during a session, but it does not update model weights or guarantee that any model/search engine has indexed it. Check the revision date and verify claims against current public evidence before relying on them. Do not copy private conversations or runtime data here.
